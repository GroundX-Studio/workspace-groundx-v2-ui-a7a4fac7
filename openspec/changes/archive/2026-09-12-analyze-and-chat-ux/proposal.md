## Why

Live review of the onboarding Understand/Analyze + chat surfaces surfaced four issues (2026-07-05):

1. **The Extract fields panel is hardcoded to one document shape, not composable.** `extractLiveData.ts` `CATEGORY_ORDER = ["statement","meters","charges"]` — `workflowToSchema` only picks groups **named exactly** those three and reads **one level** (`group.fields`); other group names, and every nested group (`meter_charges`), are silently dropped. `extractToValues` flattens array groups to element **[0]** — only the *first* meter and *first* charge ever render. It survived review because the widget was built against the scenario fixtures (which have exactly those three groups). Violates the tier-1 "solve to the model — render the object, don't hardcode a shape" principle.
2. **The field-detail card is low value.** FIELD / SOURCE / WHY MATCHED (which just echoes the field description) / CONFIDENCE, taking over the whole right pane, is heavier than the job needs.
3. **The chat message looks broken while citations resolve** — a bare "…" mid-render reads as stuck.
4. **Two small polish bugs:** the Understand doc-pane scrollbar wastes a right-margin gutter; the chat header's fade/cutoff eats the top of the scrolled content.

**Verified ground truth (live GroundX API + demo, 2026-07-06). OUTPUT-FIRST.** The render **structure comes from the extraction OUTPUT tree** (`getDocumentExtract`), walked as-received; the **labels/types/instructions come from the workflow schema fields, looked up by field name**. The demo workflow SCHEMA is **flat** — three sibling groups `statement`/`meters`/`charges`; `charges.fields` includes `meter_id` (an FK). The demo OUTPUT is **reshaped server-side** by Arcadia business logic: statement scalars **hoisted to root** (no `statement` wrapper); matched charges nested as **`meters[].meter_charges`** (a re-keyed projection — only some charge fields, e.g. `line_amount`/`line_currency`/`line_label`); unmatched charges in a synthesized top-level **`account_charges`**; NO top-level `charges`. There are **no** `__conflicts`/`*_decisions` attrs and **no** `{value,confidence}` dicts in the real output. The current code already reads labels by name (`extractLiveData.ts:58` `fieldFromPrompt` over `workflow.extract.<group>.fields.<id>.prompt`); the render joins output→schema **by field name**. This is **NOT v1-gated** and **NOT blocked by wave step 0** — the legacy demo output already has the nested/hoisted shape and the legacy workflow already carries the field labels, so the render works on the current demo today.

## What Changes

**Composable Extract render (1).** Drive the fields panel by **walking the extraction OUTPUT tree** and joining each output field to its schema field def **by name** for labels/types. STRUCTURE comes from the output: top-level scalar fields + top-level array groups (`meters`, `account_charges`), and within a meter its nested `meter_charges` array. A *scalar* field renders a row; an *array group* renders **every** instance; each instance renders its scalar fields **and** its nested arrays (charges under each meter), to any depth. The server already did the reshaping (`match_attrs`/hoist/project) — the app does NOT reassemble and does NOT derive structure from the schema. No group-name allow-list, no `[0]` flatten.

**Retire the card → hover/click highlights (2).** Remove the **inline provenance block** — the `<Box data-testid="field-provenance-panel">` (SOURCE + WHY MATCHED) inside `Extract.tsx` (surgery in a 1772-line file, not a separate component); a field-instance row drives the PDF bounding-box highlight on hover/focus (click to pin). Confidence band (shipped) stays inline on the row.

**Thinking stream (3).** Replace the bare "…" with a live **thinking stream** carrying (a) the app's own human-readable status lines ("reading page 1", "matching charge codes", "verifying citations") streamed during the turn, **and** (b) the model's real reasoning **when the provider exposes it**. Mechanics (researched 2026-07-05): chat rides `/chat/completions`, which surfaces **no** reasoning — model reasoning needs the OpenAI **Responses API** (`reasoning.summary`) or, on an Anthropic provider, Messages `thinking:{type:"adaptive",display:"summarized"}` streamed as `thinking_delta`. So (a) ships now over the existing `chatCompletionStream` seam; (b) is **in scope** — this change wires the OpenAI **Responses API** path (behind the `LlmClient` seam) and enables it for our chat models, with the same adapter interface for Anthropic; it still degrades to (a)-only when a provider/model exposes no reasoning.

**Polish (4).** Scrollbar flush to the pane edge (no wasted gutter); chat header pads the text, not the scroll region, so scrolled content reaches the top. (The highlight-bbox padding also raised in review already shipped via `overlayPxRect(padPx)`.)

**Render is output-first — structure from output, labels from schema-by-name.** STRUCTURE comes from the `getDocumentExtract` OUTPUT tree, walked as-received (statement scalars at root · `meters[].meter_charges` · top-level `account_charges` — NO in-app re-nesting/group-by). LABELS/TYPES/instructions come from the workflow schema fields looked up **by field name**: a charge field like `line_amount` under `meter_charges` OR `account_charges` maps to the `charges` group's field def by name. So the schema is a **flat field-def dictionary** keyed by field name (with group context); the render joins output→schema by name. **Hiding = don't render output keys that have no matching schema field.** `account_charges`/`meters`/`meter_charges` are STRUCTURE containers (render them); their leaf fields ARE schema fields (render them). No `leafFields` allow-list, no hardcoded `__conflicts` pattern (confirmed absent in real data). Confidence: the real output has NO `{value,confidence}` dicts, so the band is **dormant** — keep the unwrap defensively but mark it dormant, not a verified feature. **Persisted-Template mismatch:** the committed Extract Template uses a flat `{categories}` shape (`shared/src/index.ts:426` `extractBodySchema`); the render reads LIVE extraction output + LIVE workflow schema, **not** the persisted Template — if any pin-to-Template path bridges to the render, that shape gap is flagged, not silently assumed equal. **The schema editor + workflow save are carved into a separate change, `extract-workflow-authoring`** (see that change).

In scope HERE: the read-only Extract render + per-instance geometry/confidence + hover interaction (1,2); the chat thinking-stream channel + app narration + FE rendering + the OpenAI Responses-API reasoning path (3); the two CSS polishes (4). Out of scope (→ `extract-workflow-authoring`): the schema editor, YAML authoring, and workflow save. Also out: changing what a committed Template/Result *contains*; a forced default provider swap.

## Capabilities

### Modified Capabilities
- `ui-views`: F3 Extract renders the full extracted object recursively by walking the extraction OUTPUT tree (all instances, nested arrays, no hardcoded group names, labels joined from the schema by field name); the inline field-provenance block is retired for hover/click PDF highlighting per field-instance; the chat renders a thinking-stream state instead of the bare `LoadingDots` "…"; the doc-pane scrollbar sits flush and the chat header no longer clips scrolled content.
- `chat-routing`: a turn emits a **thinking stream** — ordered status events (app-authored narration) plus, when the configured LLM provider/API exposes reasoning, the model's reasoning summary — over the existing streaming seam, ahead of the final rendered message.
